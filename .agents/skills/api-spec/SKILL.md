# API Spec

依使用者指定的 API 或函式名稱，查閱目前專案實作，整理給不懂程式的人看的欄位規格。查詢功能（例如 `readEvents`）預設列出回傳供顯示的欄位；新增或修改功能（例如 `createEvent`）預設列出填寫欄位。使用者指定輸入或顯示欄位時，以指定範圍為準。使用繁體中文與日常用語。

## 確認規格

- 讀取適用的專案指引，使用 `rg` 搜尋指定名稱，追蹤路由、處理函式及輸入驗證。以實作為準，不將內部函式或資料庫所有欄位當作 API 輸入。
- 填寫欄位依請求內容、查詢條件與路徑參數確認。顯示欄位依實際回傳內容、資料查詢選取欄位及前端使用方式確認；清單應展開每筆資料的欄位，不只列出外層清單名稱。不混入內部設定、環境變數或未回傳的資料庫欄位。
- 依驗證邏輯及預設值判斷是否必填，不僅依範例是否出現判斷。資訊不足時標示「未確認」，不猜測。
- 名稱對應多個操作時，依上下文辨識；仍無法辨識時列出候選名稱供選擇。找不到名稱時，簡短說明並提供找到的相關名稱。
- 以靜態讀取確認，不讀取 `.env`、憑證或 token，也不呼叫會修改資料的 API。

## 呈現方式

標題使用「功能中文名稱（函式名稱）」，接著只列出四欄表格：「欄位英文」、「欄位中文」、「必填」、「資料型態」。

- 欄位英文保留實際名稱，欄位中文改寫為易懂名稱。
- 必填使用「是」、「否」或「未確認」。
- 顯示欄位的「必填」一律填「不適用」，不把回傳資料是否有值誤當成使用者必填要求。
- 資料型態使用中文，例如「文字」、「日期」、「日期時間」、「整數」、「數字」、「是／否」、「清單」、「資料組合」。依實作選擇，不把含時間的資料簡化成只有日期。
- 日期即使以文字傳送，確認其用途後仍顯示「日期」或「日期時間」；布林值顯示「是／否」。
- 不預設加入網址、HTTP 方法、程式碼、JSON 範例、驗證實作、資料庫細節、完整回應結構或額外欄位。只有使用者另行要求時才補充。
- 查詢功能沒有輸入欄位時，仍須列出顯示欄位。指定查看輸入且沒有輸入欄位時，才說明「這個功能不需要填寫欄位」；沒有顯示欄位則說明「這個功能沒有回傳可顯示的欄位」。除非使用者要求，直接回覆，不另建規格文件或修改程式。
